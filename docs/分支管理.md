---

## 🧭 分支管理说明（双人协作开发）

### 📌 分支结构约定

| 分支名         | 说明                                                                 |
|----------------|----------------------------------------------------------------------|
| `master`       | 正式展示分支，配置了独立 CI/CD 与域名，用于稳定版本的发布与展示     |
| `dev`          | 主集成分支，用于日常开发集成与测试，触发开发环境的 CI/CD             |
| `dev-backend`  | 后端开发分支，由后端负责人维护                                       |
| `dev-frontend` | 前端开发分支，由前端负责人维护                                       |

---

### 👥 各自操作流程

#### ✅ 开发前：保持分支与 `dev` 同步

在自己的开发分支上执行：

```bash
git checkout dev-backend        # 或 dev-frontend
git pull --rebase origin dev    # 拉取并 rebase 最新 dev 更改
```

> ✅ **建议使用 `--rebase` 而非 `merge`**，保持提交历史清晰、线性，便于审查与回溯。

---

#### 💻 开发中：正常提交代码

```bash
git add .
git commit -m "描述你的更改"
git push origin dev-backend     # 或 dev-frontend
```

---

#### 🔄 合并到 `dev`：准备集成和测试

1. 切换到 `dev` 分支并更新：

   ```bash
   git checkout dev
   git pull origin dev
   ```

2. 合并你的开发分支：

   ```bash
   git merge dev-backend        # 或 dev-frontend
   ```

   或使用 rebase：

   ```bash
   git rebase dev-backend
   ```

3. 推送到远程触发开发环境 CI/CD：

   ```bash
   git push origin dev
   ```

---

### 🚀 发布到 `master`：部署正式展示版本

1. 确保 `dev` 分支稳定并通过测试  
2. 切换到 `master` 分支并更新：

   ```bash
   git checkout master
   git pull origin master
   ```

3. 合并 `dev` 分支的最新内容：

   ```bash
   git merge dev
   ```

   或使用 rebase（推荐保持线性历史）：

   ```bash
   git rebase dev
   ```

4. 推送到远程触发正式环境 CI/CD：

   ```bash
   git push origin master
   ```

> 🌐 `master` 分支已配置独立域名与 CI/CD，用于对外展示，请确保合并前内容稳定可靠。

---

### 🧼 推荐协作习惯

- 每次开发前 `pull --rebase` 保持分支同步  
- 合并前确保目标分支是最新的  
- 使用清晰的 commit 信息，便于审查  
- `master` 分支仅用于展示版本，避免频繁提交  
- 所有展示内容应先在 `dev` 中验证通过再发布到 `master`
